# 命盘归档与反馈协议

## 数据位置与权限

运行目录由 AstrBot 的 `get_astrbot_data_path()` 决定，数据库固定为其下的 `plugin_data/astrbot_plugin_ziwei/archives.sqlite3`。不使用插件代码目录或框架 KV 存生辰，不依赖当前工作目录。普通插件更新和重载保留数据库；删除 AstrBot 数据目录仍会删除档案。停用插件并备份整个该目录，可同时保留 SQLite 及其 WAL 文件；不在运行中单独复制主数据库文件。

SQLite `user_version=1`，拒绝以旧程序打开未知较新版本。每次成功排盘先持久化快照，再确认成功；存储失败不会返回“已归档”。每个快照有随机 ID，相同原始出生输入、规则版本和配置另有命盘族指纹。本人档案按真实事件的平台实例、群、用户隔离；工具参数不接受用户或群身份。群关闭后拒绝读取，重新开启恢复访问；档案不会随缓存清空而删除。

| 表 | 内容 |
| --- | --- |
| `charts` | 独立排盘快照、拥有者指纹、命盘族、创建时间 |
| `readings` | 关联命盘、作用域、主题、知识快照、盘面特征、队列与总结状态 |
| `turns` | 本次问题、相关追问、回答及用户反馈，保留顺序和事件去重键 |
| `groups_state` | 队列和共享参考的群开关镜像，真实授权仍以框架 KV 为准 |

数据库是本地明文档案，包含原始生辰及相关问答，服务器管理员可读取。日志只记录错误类别，不写模型提示、回复正文或出生输入；框架自身日志与聊天历史不由插件清理。

## 按需分析与闭环

1. 普通排盘只计算、展示和存档，不建立分析、不调用总结模型。
2. 用户提出具体问题后，主 AI 调用 `ziwei_analysis_context`，选择本命／大运／流年及主题。记录当前真实消息，不允许工具传入虚构问题或反馈文本。
3. 同一消息只关联一个分析范围，相关追问／反馈由 `ziwei_continue_reading` 绑定。不同用户、不同盘的无关聊天不进入案例。
4. 在本次事件实例上观察 `send`／`send_streaming`，保留原调用参数和返回值。普通发送成功返回后登记文字；流式调用完整返回后登记实际消费的文字片段。流式内部普通发送不重复计数。失败或采集超限标记记录不完整，不能进入闭环。
5. 主 AI 判断用户已经反馈、问题闭环时调用 `ziwei_finish_reading(..., feedback_complete=true)`。程序同时要求已有回答、其后真实用户反馈，而且反馈不能与回答属于同一条用户消息。没有反馈不会自动结束；“谢谢”可以表示对话结束，但不能视为预测得到验证。
6. 工具立即返回 `queued`，独立后台消费者调用已有 AstrBot 聊天模型，`contexts=[]`，无工具、无会话写入、无群消息发送。默认使用当前会话模型，也可设置 `summary_provider_id`。请求只含这张盘、这次作用域、已查阅知识与相关问答反馈。一次调用结束即释放临时上下文，主对话继续工作。
7. 总结 JSON 必须包含问题摘要、分析摘要、用户反馈、修正、未验证事项、反馈类别及真实反馈序号。只有结构校验通过且群仍授权时才保存为 `archived`。不把用户陈述升级为客观验证。

状态为 `active → queued → running → archived`。失败间隔至少 60 秒，自动尝试最多三次，随后 `failed`；用户可要求 `ziwei_retry_summary` 重试原任务。重载取消在途请求并保留排队数据；异常退出后，将遗留 `running` 恢复为 `queued`。按单插件实例、一个消费者设计。

单次初始问题最多 6000 字，单条记录最多 12000 字、一次分析最多 60 条；模型输入最多 100000 字符，总结超时 90 秒。超限拒绝，不静默截断成完整案例；原记录保留。发送或采集不完整时，应重新建立较小范围分析。图片／语音本身不转录为回答文本；只有没有抛出异常的适配器调用及其文本可采集，这不证明接收者实际阅读或平台未静默丢弃消息。

## 历史参考与脱敏

`ziwei_reading_history` 只查本人当前群内同命盘族的闭环摘要，分页返回，供当前分析内部参考。`ziwei_reference_cases` 从当前分析自动取得主题、作用域及配置特征，不能指定他人身份。

共享检索限定同作用域、同主题、同计算规则与配置，至少有一个所问宫位主星或四化特征重合。扫描最近 500 条已归档且所在群仍开启的记录，每个其他用户最多一案；至少三个不同用户匹配时才返回，最多八条案例投影。返回字段仅有作用域、主题、匹配的宫位星曜／四化标签及 `supported`／`contradicted`／`mixed`／`unverified` 反馈类别。不会返回姓名、群号、用户号、生辰、地址、原始问答、自由文本摘要或可追溯档案 ID。匹配不是相同命运，也不是精确事件检索。

跨用户的自由文本永远不会进入主 AI；即使总结 JSON 中包含个人信息，也不会出现在共享查询结果中。参考用途限制同时写入系统提示、工具说明与返回值：不得披露参考内容、引用历史原文、展示样本统计或宣称准确率。对主 AI 输出措辞的约束仍依赖模型遵循指令；本地字段隔离不等于验证所有在线模型绝不复述允许返回的抽象标签。

接口核对：[AstrBot 模型调用与工具](https://docs.astrbot.app/dev/star/guides/ai.html)、[事件及临时动态提示](https://docs.astrbot.app/dev/star/guides/listen-message-event.html)。2026-10-14 检查官方 `respond/stage.py`：流式发送直接返回、普通发送异常后仍可能触发发送后钩子，因此不能仅靠 `after_message_sent` 判定回答完整送出。
