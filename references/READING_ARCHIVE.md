# 命盘归档与反馈协议

## 数据位置与权限

运行目录由 AstrBot 的 `get_astrbot_data_path()` 决定，数据库固定为其下的 `plugin_data/astrbot_plugin_ziwei/archives.sqlite3`。不使用插件代码目录或框架 KV 存生辰，不依赖当前工作目录。普通插件更新和重载保留数据库；删除 AstrBot 数据目录仍会删除档案。停用插件并备份整个该目录，可同时保留 SQLite 及其 WAL 文件；不在运行中单独复制主数据库文件。

SQLite `user_version=5`，从版本 1 增量建立额度表，从版本 2 增量建立图谱表，从版本 3 增量建立独立定盘会话表，从版本 4 增量建立定盘总图投递表，保留原有档案和已确认额度；拒绝以旧程序打开未知较新版本。每次成功排盘先持久化快照，再确认成功；存储失败不会返回“已归档”。普通命盘快照有随机 ID，相同原始出生输入、规则版本和配置另有命盘族指纹；定盘批次的完整候选先保存在独立会话中。本人档案按真实事件的平台实例、群、用户隔离；工具参数不接受用户或群身份。群关闭后拒绝读取，重新开启恢复访问；档案不会随缓存清空而删除。

| 表 | 内容 |
| --- | --- |
| `charts` | 独立排盘快照、拥有者指纹、命盘族、创建时间 |
| `readings` | 关联命盘、作用域、主题、知识快照、盘面特征、队列与总结状态 |
| `turns` | 本次问题、相关追问、回答及用户反馈，保留顺序和事件去重键 |
| `groups_state` | 队列和共享参考的群开关镜像，真实授权仍以框架 KV 为准 |
| `ai_usage` | 平台实例及用户的哈希指纹、额度类别、去重键、时间及计算中的预占状态；不存生辰或问题正文 |
| `life_atlases` | 关联本人命盘、主题、创建时间与完整候选窗口证据，包括本命副本、P1 规则版本及所用知识快照；不保存逐年完整盘或 PNG |
| `rectifications` | 独立定盘会话、请求和规则配置、完整候选盘与时间范围、管理员选定、比较评价、总结及失败状态 |
| `rectification_turns` | 定盘真实问题、已发送回答及反馈，按会话与事件去重并保留顺序 |
| `rectification_deliveries` | 本人真实消息的单张总图发送状态；成功去重、失败重试及重载中断恢复，不保存图片或发送正文 |
| `rectification_contexts` | 本会话已读取的候选事实、作用域、主题与知识来源快照，按完整内容指纹去重 |

数据库是本地明文档案，包含原始生辰及相关问答，服务器管理员可读取。日志只记录错误类别，不写模型提示、回复正文或出生输入；框架自身日志与聊天历史不由插件清理。

`/人生`、`/紫微 图谱` 先检查当前群授权，再解析或读取本人档案，计算后与图片发送前再次检查。新出生资料的来源盘与图谱证据在同一事务写入，任一写入失败则一起回滚；已有命盘只关联原 ID，不改变原流年或运限档案。图片在内存生成；图谱保存不进入额度表，也不建立分析记录或触发总结。无参选择按出生资料和规则配置的命盘族去重，多份档案需明确选择，不自动猜测。

AI 解盘问题、生年排盘、大运（含童限）排盘分别限制为滚动 3600 秒内 6、2、3 次，同一平台实例的同一用户跨群共享。问题以真实消息去重，登记追问与扣额度使用同一事务；知识、历史参考等分析数据入口也检查当前消息额度。纯反馈、闭环、重试总结、读取及重发旧盘不扣次数。直接指令排盘不进入额度表；群授权仍生效。流年排盘无新增次数限制，流年解盘使用问题额度。

AI 排盘在计算前事务预占额度，成功存档的同一事务将其确认为已使用；计算或存储失败释放预占，重启时清理中断遗留的预占。已存档但发送失败不会退款，可以重发该档案图片。已确认额度保留至滚动窗口到期，不因缓存清理、重载或群开关重置。部署仅支持一个插件实例使用此数据库，与总结队列一致。

## 按需分析与闭环

1. 普通排盘只计算、展示和存档，不建立分析、不调用总结模型。
2. 用户提出具体问题后，主 AI 调用 `ziwei_analysis_context`，选择本命／大运／流年及主题。记录当前真实消息，不允许工具传入虚构问题或反馈文本。
3. 同一消息只关联一个分析范围，相关追问／反馈由 `ziwei_continue_reading` 绑定。不同用户、不同盘的无关聊天不进入案例。
4. 在本次事件实例上观察 `send`／`send_streaming`，保留原调用参数和返回值。普通发送成功返回后登记文字；流式调用完整返回后登记实际消费的文字片段。流式内部普通发送不重复计数。失败或采集超限标记记录不完整，不能进入闭环。
5. 主 AI 判断用户已经反馈、问题闭环时调用 `ziwei_finish_reading(..., feedback_complete=true)`。程序同时要求已有回答、其后真实用户反馈，而且反馈不能与回答属于同一条用户消息。没有反馈不会自动结束；“谢谢”可以表示对话结束，但不能视为预测得到验证。
6. 工具立即返回 `queued`，独立后台消费者调用已有 AstrBot 聊天模型，`contexts=[]`，无工具、无会话写入、无群消息发送。默认使用当前会话模型，也可设置 `summary_provider_id`。请求只含这张盘、这次作用域、已查阅知识与相关问答反馈。一次调用结束即释放临时上下文，主对话继续工作。
7. 总结 JSON 必须包含问题摘要、分析摘要、用户反馈、修正、未验证事项、反馈类别及真实反馈序号。只有结构校验通过且群仍授权时才保存为 `archived`。不把用户陈述升级为客观验证。

状态为 `active → queued → running → archived`。失败间隔至少 60 秒，自动尝试最多三次，随后 `failed`；用户可要求 `ziwei_retry_summary` 重试原任务。重载取消在途请求并保留排队数据；异常退出后，将遗留 `running` 恢复为 `queued`。按单插件实例、一个消费者设计。

单次初始问题最多 6000 字，单条记录最多 12000 字、一次分析最多 60 条；模型输入最多 100000 字符，总结超时 90 秒。超限拒绝，不静默截断成完整案例；原记录保留。发送或采集不完整时，应重新建立较小范围分析。图片／语音本身不转录为回答文本；只有没有抛出异常的适配器调用及其文本可采集，这不证明接收者实际阅读或平台未静默丢弃消息。

## 定盘会话与独立归档

定盘要求真实事件同时满足 AstrBot 管理员身份与当前群已开启；普通群主、群管理员及私聊均不能代替这两个条件。所有会话仍按平台实例、群、用户隔离，不提供跨用户定盘档案检索。管理、读取与工具分析均复核权限；异步计算和发送前再次检查群状态。

管理员显式发送 `/紫微 定盘 <日期> <性别> [时辰=...]`，或明确要求 AI 按所给资料定盘时，由对应指令或 `ziwei_rectification_create` 创建候选批次。候选按钟表半开区间记录，包含真太阳时、换日及节气边界；代表时刻不是确定出生时刻。批次最多 32 个候选，完整候选及请求元数据在同一事务保存，同一真实创建消息及规范化参数指纹去重。AI 整批计 1 次生年排盘额度，与普通 AI 生年排盘共享每小时 2 次，保存候选与额度结算原子完成；直接指令创建免费。此时不插入普通 `charts`、不替换最近命盘缓存，也不触发总结模型。查看候选只渲染原快照；图片在内存生成。

`create`／`get` 的 `send_image=true` 以及 `总图` 指令将完整候选拼为一张图片，只发送一个图片组件。投递以本人范围与真实消息 ID 唯一关联，成功状态不可覆盖；同消息并发调用不重复发送。发送失败保留候选与已确认额度，可免费重试；重载将遗留发送中状态恢复为失败。图片发送与数据库不能形成跨平台事务，平台接收后但本地确认前进程中断可能需要人工判断是否重发，不保证平台侧严格一次交付。

创建后，管理员明确开始定盘分析。主 AI 按候选和主题分批获取真实事实及来源知识，每批至多两张；本命、大运、流年仍走原计算层，不调用人生图谱 P1 作为定盘评分。初次问题和相关追问与普通读盘共用每平台实例、每用户滚动一小时 6 次额度，同一消息分批调用只计一次；读取已有会话、总图重发及纯反馈不扣次数。只有真实已登记问题才允许取得新增分析资料，纯反馈只修正原分析。AI 不得代执行创建指令，也不得用普通排盘工具绕过候选入口和次数限制。

定盘问答使用独立的发送采集关联，一次回答只能对应一个定盘会话，不能同时关联普通读盘。原始问题、回答、反馈、已用知识快照完整保存；AI 比较保留 `support`、`conflict`、`unknown`、`evidence_sequences`、`knowledge_ids`。支持或冲突必须引用真实反馈序号与该候选已读取的知识，不接受虚构反馈和未读知识。评价不永久排除候选，不表示概率或客观验证；未获充分信息时保留多个候选。

`状态`、`查看`、`总图`、`确认`、`取消`、`重试总结` 均可显式指定会话 ID，有多个进行中会话时必须选择。只有管理员显式 `/紫微 定盘 确认 c01 [会话ID]` 才将该候选作为新的 `charts` 快照保存并放入当前缓存；正式盘附 `rectification` 来源，包括会话、候选、原时间范围与 `representative_only=true`。重复确认同一候选返回原正式盘，不能改选覆盖；已确认会话不能取消。尚未确认的会话可取消，所有原始档案保留。

会话的 `status`（`active`／`selected`／`cancelled`）与 `summary_status`（`none → queued → running → archived`，失败为 `failed`）分别保存，确认候选与反馈闭环互不替代。主 AI 只有在已发送回答之后收到另一真实消息的反馈、且没有未回答问题时才可排队总结；发送或采集不完整不能闭环。总结可保留多个候选，无须先选出唯一时辰。

独立消费者复用已有 AstrBot 模型，默认按原会话选择 provider，也可用已有 `summary_provider_id` 配置；不新增 API Key。模型只收到本会话候选计算摘要、比较评价、已用知识与对应问答反馈，`contexts=[]`，无工具、无主对话写入、无群发送。完整候选与知识仍留在原档案中，不将展示摘要冒充原始数据。总结要求保留冲突、修正和未验证事项；管理员选定仅代表选择。

群关闭暂停访问及未完成总结，永久档案与已计额度保留；重载取消在途总结并恢复队列。失败按现有消费者策略最多自动尝试三次，之后可显式 `重试总结`。单条定盘消息最多 12000 字、每会话最多 60 条；上下文累计最多 2 MiB、120 份，超限拒绝并保留已有记录。定盘档案不加入普通跨用户案例检索。

## 历史参考与脱敏

`ziwei_reading_history` 只查本人当前群内同命盘族的闭环摘要，分页返回，供当前分析内部参考。`ziwei_reference_cases` 从当前分析自动取得主题、作用域及配置特征，不能指定他人身份。

共享检索限定同作用域、同主题、同计算规则与配置，至少有一个所问宫位主星或四化特征重合。扫描最近 500 条已归档且所在群仍开启的记录，每个其他用户最多一案；至少三个不同用户匹配时才返回，最多八条案例投影。返回字段仅有作用域、主题、匹配的宫位星曜／四化标签及 `supported`／`contradicted`／`mixed`／`unverified` 反馈类别。不会返回姓名、群号、用户号、生辰、地址、原始问答、自由文本摘要或可追溯档案 ID。匹配不是相同命运，也不是精确事件检索。

跨用户的自由文本永远不会进入主 AI；即使总结 JSON 中包含个人信息，也不会出现在共享查询结果中。参考用途限制同时写入系统提示、工具说明与返回值：不得披露参考内容、引用历史原文、展示样本统计或宣称准确率。对主 AI 输出措辞的约束仍依赖模型遵循指令；本地字段隔离不等于验证所有在线模型绝不复述允许返回的抽象标签。

接口核对：[AstrBot 模型调用与工具](https://docs.astrbot.app/dev/star/guides/ai.html)、[事件及临时动态提示](https://docs.astrbot.app/dev/star/guides/listen-message-event.html)。2026-10-14 检查官方 `respond/stage.py`：流式发送直接返回、普通发送异常后仍可能触发发送后钩子，因此不能仅靠 `after_message_sent` 判定回答完整送出。
